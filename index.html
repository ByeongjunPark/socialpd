    PART 2

    AI 피드백 수용일지 템플릿 만들기

    AI가 학생의 제안서를 논박하면, 학생은 그 피드백을 받아들일지 스스로 판단해 일지에 적고 글을 고칩니다. 구글시트와 앱스스크립트, 업스테이지 AI로 이 흐름을 만들어 봅니다.

    실습 2단계 + 심화 1Google SheetsApps ScriptUpstage AI
    📱 완성된 웹앱 화면 미리보기 클릭하면 크게 볼 수 있어요
    🗺️ 수업 흐름 한눈에 보기 예시: 인권 개선 정책 제안서
    1. 학생
      📝

      제안서 작성

      인권 개선 정책 제안서 초안을 씁니다.

      먼저 스스로 생각하기AI보다 내 생각을 먼저 꺼내 봅니다.
    2. AI 챗봇
      🤖

      AI 논박

      제안서를 읽고 구체적으로 반론합니다.

      실현가능성교과 내용 정합성정책의 구체성
      생산적인 막힘답 대신 반론과 질문을 받아 다시 생각하게 됩니다.
    3. 학생
      📓

      피드백 수용일지

      대화 내역을 보며 반론마다 받아들일지 판단하고 근거를 적습니다.

      수용부분 수용불수용
      피드백을 판단하기AI의 말도 따져 보고 고를 대상입니다.
    4. 학생
      ✅

      수정 · 최종 제출

      일지의 판단에 따라 제안서를 고쳐 제출합니다.

      피드백을 행동으로판단한 내용을 실제 글에 반영합니다.
    💡 AI는 고쳐 주지 않고 논박만 합니다. 어떤 피드백을 받아들일지는 학생이 판단하며, 이 판단 과정이 평가 대상이 됩니다.

    🤔 왜 이렇게 설계했을까요?

    AI가 바로 고쳐 주면 글은 금방 좋아지지만, 학생에게 남는 것은 많지 않습니다. 이 흐름은 일부러 한 번 더 생각하게 만드는 장치를 넣고, 학생이 피드백을 스스로 다루는 힘을 기르도록 짜여 있습니다.

    🧗

    바람직한 어려움

    Desirable Difficulties · Bjork (1994)

    쉽게 배운 것은 쉽게 잊힙니다. 배우는 순간에는 조금 힘들어도, 스스로 떠올리고 따져 보는 과정을 거친 내용이 더 오래 남고 다른 상황에도 잘 옮겨 쓰입니다. 운동할 때 적당한 무게가 근육을 키우는 것과 비슷합니다.

    • ① AI에게 묻기 전에 초안부터 직접 씁니다. 스스로 만들어 본 생각이 다음 단계의 출발점이 됩니다.
    • ② AI는 고친 문장 대신 반론과 질문을 줍니다. 생각을 AI에게 통째로 맡기는 ‘인지 외주화’를 막고, 학생이 생각을 이어 가게 합니다.
    • ③ ④ 반론을 다시 읽고 판단한 뒤 내 손으로 고칩니다. 같은 내용을 여러 번 다시 꺼내 쓰며 이해가 깊어집니다.
    ⚖️ ‘바람직한’ 정도가 중요합니다. 너무 어려우면 그냥 포기합니다. 그래서 논박 기준을 3가지로 좁혀 주고, AI가 질문 형태로 방향을 살짝 알려 주는 발판(스캐폴딩)을 함께 둡니다.
    🔍

    피드백 리터러시

    Feedback Literacy · Carless & Boud (2018)

    피드백은 ‘받는 것’이 아니라 ‘쓰는 것’입니다. 피드백을 이해하고, 맞는지 따져 보고, 내 글에 반영하는 능력을 피드백 리터러시라고 합니다. 이 능력은 저절로 생기지 않아서 수업에서 연습할 기회가 필요합니다.

    피드백 리터러시 요소이 수업에서는
    피드백의 가치 알기② 반론을 ‘지적’이 아니라 글을 좋게 만드는 재료로 받아들입니다.
    감정 다루기② 반박을 받아도 상대가 AI라 덜 위축되고, 재반박하며 차분히 대화합니다.
    판단하기③ 반론마다 수용·부분 수용·불수용을 고르고 근거를 씁니다.
    행동으로 옮기기④ 판단한 내용을 실제로 제안서에 반영해 고칩니다.
    🚩 ‘불수용’도 좋은 답입니다. AI도 틀립니다. 미리보기 화면에서도 AI가 출처를 확인하기 어려운 통계를 근거로 듭니다. “이 근거가 사실인가?”를 따져 보고 근거를 들어 거절하는 것 역시 중요한 피드백 리터러시입니다.

    🧑‍🏫 교사가 챙길 3가지

    1. 결과물보다 판단 과정을 봅니다. 최종 글의 완성도와 함께, 수용일지에 쓴 판단의 근거가 타당한지 평가합니다.
    2. 불수용을 칭찬합니다. AI 말을 다 받아들인 학생보다, 근거를 들어 걸러 낸 학생이 더 깊이 생각한 것일 수 있습니다.
    3. 어려움의 수준을 조절합니다. 막혀서 멈춘 학생에게는 논박 기준 하나만 골라 대화하게 하는 등 부담을 줄여 줍니다.
    2-1

    구글시트 사본 만들기 · 웹앱 배포

    챗봇 코드가 들어 있는 구글시트를 복사하고, 앱스스크립트 웹앱으로 배포합니다.
    📊 구글시트 사본 만들기 ↗
    📌 시트를 복사하면 연결된 앱스스크립트 코드도 함께 복사됩니다. 배포 전에 2-2에서 API 키를 먼저 발급받아 두세요.
    앱스스크립트 웹앱 배포 방법 보기

    1. 앱스스크립트 열기

      사본으로 만든 구글시트 상단 메뉴에서 확장 프로그램 → Apps Script를 클릭합니다. 새 탭에 스크립트 편집기가 열립니다.

    2. 스크립트 속성에 API 키 등록

      API 키는 코드에 직접 쓰지 않고 스크립트 속성에 안전하게 저장합니다.

      • 편집기 왼쪽 메뉴 맨 아래 ⚙️ 프로젝트 설정 클릭
      • 화면 맨 아래 스크립트 속성 → 스크립트 속성 추가 클릭
      • 속성: UPSTAGE_API_KEY (대소문자·밑줄까지 정확히)
      • 값: 2-2에서 발급받은 API 키 붙여 넣기 (앞뒤 공백 없이)
      • 스크립트 속성 저장 클릭 후, 왼쪽 <> 편집기로 돌아오기
      💡 스크립트 속성에 넣은 키는 시트를 공유하거나 학생이 웹앱을 써도 보이지 않습니다. 키를 바꿀 때도 여기서 값만 수정하면 됩니다.

    3. 새 배포 만들기

      편집기 오른쪽 위 파란색 배포 → 새 배포를 클릭합니다.

    4. 유형을 ‘웹 앱’으로 선택

      유형 선택 옆 ⚙️ 톱니바퀴 → 웹 앱을 선택하고 아래와 같이 설정합니다.

      • 설명: 자유롭게 (예: 논박 챗봇 v1)
      • 다음 사용자 인증 정보로 실행: 나
      • 액세스 권한이 있는 사용자: 모든 사용자 (학교 계정이면 ○○교육청/학교 내 모든 사용자도 가능)

    5. 배포 · 액세스 승인

      배포를 누르면 권한 요청이 뜹니다. 액세스 승인 → 내 구글 계정을 선택합니다.

    6. (개인 계정) ‘확인되지 않은 앱’ 경고 넘어가기

      개인 지메일 계정이면 “Google에서 확인하지 않은 앱” 경고 화면이 나옵니다. 내가 만든 스크립트이므로 다음 순서로 진행하면 됩니다.

      • 왼쪽 아래 더보기(또는 고급) 클릭
      • 맨 아래 ○○(으)로 이동(안전하지 않음) 클릭
      • 권한 목록 확인 후 허용 클릭
      💡 ‘안전하지 않음’은 구글 검수를 받지 않은 앱이라는 뜻일 뿐, 본인이 복사한 스크립트라면 괜찮습니다.

    7. 웹 앱 URL 복사 → 학생에게 공유

      배포가 끝나면 나오는 웹 앱 URL(https://script.google.com/macros/s/.../exec)을 복사해 학생에게 안내합니다.

    ⚠️ 코드를 수정했다면? 배포 → 배포 관리 → ✏️ 수정 → 버전을 새 버전으로 바꾸고 배포해야 학생 화면에 반영됩니다. (URL은 그대로 유지)

## 1. 프로젝트 개요 및 목표

### 1.1 프로젝트명

* **사회과 인권 개선 정책 제안 및 AI 피드백 성찰 웹앱** (Google Apps Script 기반)

### 1.2 개발 배경 및 목적

* 중·고등학교 사회 수업에서 학생들이 직접 지역사회 또는 학교의 인권 문제 개선 정책 제안서를 작성하고, AI 챗봇과의 논박을 통해 실현 가능성, 교과 내용 정합성, 정책 구체성을 다각도로 검증함.

* **자율 이동 제약**: 1단계부터 4단계까지 자유롭게 이전/다음 단계로 이동 가능하며, 단계별 임시저장 기능 제공

## 2. 사용자 역할 및 로그인 체계

### 2.1 인증 및 학생 정보 관리

## 3. 데이터베이스(Google Sheets) 구조 및 자동 설정 요구사항

### 3.1 탭 및 헤더 자동 생성 (`initSpreadsheetSheets` 함수)

앱 실행 시 또는 관리자 초기화 시 구글 시트에 다음 2개 탭이 존재하는지 확인하고, 없을 경우 자동 생성 및 헤더 열을 작성해야 함.

#### [탭 1] `Users` (사용자 데이터)

| 열 번호 | 헤더 명칭 | 설명 |
| --- | --- | --- |
| A | `학번` | 학생 학번 (Unique Key) |
| B | `이름` | 학생 이름 |
| C | `비밀번호_해시` | SHA-256 해싱된 비밀번호 |
| D | `생성일시` | 가입/최초 로그인 일시 |
| E | `최종접속일시` | 최근 로그인 일시 |

#### [탭 2] `Proposals` (제안서 및 대화/성찰 데이터)

| 열 번호 | 헤더 명칭 | 설명 |
| --- | --- | --- |
| A | `학번` | 학생 학번 |
| B | `이름` | 학생 이름 |
| C | `1단계_제안서_초안` | JSON 형식 (정책명, 대상, 문제점, 실행방안, 기대효과) |
| D | `2단계_AI대화내역` | JSON 배열 형식 (User/Assistant 메시지 기록) |
| E | `3단계_성찰일지` | 수용/비수용 판단 및 피드백 성찰 일지 텍스트 |
| F | `4단계_최종_제안서` | JSON 형식 (수정된 최종 정책 제안서) |
| G | `현재단계` | 현재 진행 중인 단계 (1, 2, 3, 4) |
| H | `임시저장일시` | 최근 저장 일시 |
| I | `최종제출여부` | TRUE / FALSE |
| J | `최종제출일시` | 최종 제출 완료 일시 |

## 4. 단계별 기능 및 사용자 경험(UX) 흐름

### 4.1 전체 UX 단계 구조

* **[로그인]** ➔ **[1단계: 제안서 초안 작성]** ⇄ **[2단계: AI 논박 & 피드백 챗봇]** ⇄ **[3단계: 성찰 일지 작성]** ⇄ **[4단계: 최종 수정 및 제출]**
* 상단에 단계 프로그레스 바(Step Indicator)를 두어 자유롭게 클릭하거나 '이전/다음' 버튼을 통해 단계 이동 가능.

---

### 4.2 단계별 구체 사양

#### [로그인 화면]

* 입력 항목: 학번 (예: 20101), 이름 (예: 홍길동), 비밀번호
* [시작하기] 버튼 클릭 시 로그인/가입 처리 후 1단계로 이동.

#### [1단계: 인권 개선 정책 제안서 초안 작성]

* **입력 양식**:
1. 정책/사업 제목
2. 적용 대상 (예: 학생, 지역 주민, 노약자 등)
3. 해결하고자 하는 인권 문제 및 필요성
4. 구체적 정책 실행 방안
5. 기대 효과

* **주요 기능**:
* `[임시 저장]` 버튼: 입력 내용을 구글 시트에 실시간 반영.
* `[다음 단계로 (AI 피드백 받기)]` 버튼: 내용 저장 후 2단계로 이동.

#### [2단계: AI 논박 & 챗봇 피드백]

* **화면 구성**:
* **좌측(또는 상단 접이식)**: 1단계에서 작성한 제안서 초안 요약 보기.
* **우측(또는 메인)**: AI 챗봇 대화창.

* **AI 챗봇 동작 로직**:
* 2단계 최초 진입 시, 1단계 제안서를 바탕으로 AI가 자동 첫 논박 메시지 생성.
* **평가 및 논박 기준 3가지**:
1. **실현 가능성**: 예산, 법적/행정적 제약, 실행 기관의 현실성 등
2. **교과 내용 정합성**: 사회과 인권 관련 개념(기본권, 인권 침해, 차별 금지 등)과의 부합 여부
3. **정책의 구체성**: 누구나 실행할 수 있을 만큼 구체적인 절차와 방법 제시 여부

* 학생이 질문/반론을 입력하면 AI가 실시간 답변(Upstage API).
* 대화 내역은 JSON 형태로 자동 기록되며 구글 시트에 저장.

* **주요 기능**:
* `[이전 단계로 (초안 수정)]` 버튼: 1단계로 이동.
* `[다음 단계로 (성찰 일지 작성)]` 버튼: 3단계로 이동.

#### [3단계: AI 피드백 수용 성찰 일지 작성]

* **화면 구성**:
* **좌측**: 2단계에서 진행한 AI와의 전체 대화 내역 열람창.
* **우측**: 성찰 일지 작성 폼.

* **성찰 일지 질문 항목**:
1. AI의 지적/피드백 중 **수용한 내용**과 그 이유
2. AI의 지적/피드백 중 **수용하지 않거나 반박한 내용**과 그 이유
3. 최종 제안서 작성을 위해 **수정 및 보완할 핵심 방향**

* **주요 기능**:
* `[임시 저장]` 버튼
* `[이전 단계로]` / `[다음 단계로 (최종 제출)]` 버튼.

#### [4단계: 최종 제안서 수정 및 제출]

* **화면 구성**:
* 1단계 초안 및 3단계 성찰 일지 내용이 자동으로 불러와짐.
* 최종 제안서 편집 양식 (제목, 대상, 문제점, 구체적 실행방안, 기대효과).

* **주요 기능**:
* `[임시 저장]` 버튼
* `[이전 단계로]` 버튼
* `[최종 제출하기]` 버튼: 제출 완료 안내 표시 및 `최종제출여부`를 TRUE로 업데이트. (제출 후에도 재수정 및 제출 가능)

## 5. 외부 API 연동 사양 (Upstage Solar Pro API)

### 5.1 API 호출 개요

* **Endpoint**: `https://api.upstage.ai/v1/chat/completions`
* **Method**: `POST`
* **Auth Header**: `Bearer {UPSTAGE_API_KEY}` (GAS `PropertiesService.getScriptProperties()`로 관리)

### 5.2 System Prompt 설정 (AI 논박 챗봇)

2단계 챗봇은 아래 시스템 프롬프트를 그대로 사용함. 첫 메시지는 1단계 제안서 전문을 함께 전달하여 자동 논박을 생성함.

```text
# 역할
너는 고등학교 사회 수업에서 학생이 작성한 '인권 개선 정책 제안서'를 읽고 건설적으로 논박하는 토론 파트너야.
학생의 글을 대신 고쳐 주는 것이 아니라, 학생이 스스로 글을 다시 생각하고 고칠 수 있도록 날카롭지만 존중하는 반론을 제시하는 것이 목표야.

# 논박 기준
학생의 제안서를 다음 세 가지 기준으로 검토해.
1. 실현가능성: 예산, 인력, 법·제도, 이해관계자의 반발 등을 고려할 때 이 정책이 실제로 시행될 수 있는가?
2. 교과 내용 정합성: 인권의 의미와 특성, 기본권의 종류와 제한, 인권 보장 제도 등 수업에서 배운 개념을 정확하게 사용했는가? 잘못 이해했거나 빠뜨린 개념은 없는가?
3. 정책의 구체성: 정책 대상, 시행 주체, 실행 방법, 기간, 기대 효과와 평가 방법이 구체적으로 제시되어 있는가?

# 응답 방식
- 먼저 제안서의 강점 1가지를 짧게 인정해.
- 기준마다 제안서의 문장을 직접 인용("…")하고, 그 부분에 대한 구체적인 반론이나 의문을 1~2개 제시해.
- 반론마다 근거(사례, 통계, 반대 입장의 논리 등)를 함께 제시해.
- 수정된 문장이나 정답을 직접 써 주지 말고, 학생이 고민해 볼 질문으로 마무리해.
- 마지막에 너의 논박을 번호를 붙여 3~5개로 요약해. 학생은 이 요약을 보고 피드백 수용일지에 반론마다 '수용 / 부분 수용 / 불수용'과 그 이유를 적을 거야.

# 대화 원칙
- 학생이 재반박하면, 타당한 부분은 인정하고 그렇지 않은 부분은 근거를 들어 다시 논박해. 쉽게 물러서지도, 고집하지도 마.
- 학생이 "고쳐 줘", "답 알려 줘"라고 해도 직접 써 주지 말고, 고칠 방향을 스스로 찾도록 질문해.
- 고등학생 눈높이의 쉬운 말과 존댓말을 사용해.
- 특정 집단을 비하하거나 인권 침해를 정당화하는 주장에는 동조하지 말고, 인권의 보편성을 근거로 바로잡아.
```

### 5.3 Apps Script 호출 코드 스니펫 (구현 기준)

```javascript
function callUpstageSolarPro(messagesPayload) {
  const apiKey = PropertiesService.getScriptProperties().getProperty("UPSTAGE_API_KEY");
  const url = "https://api.upstage.ai/v1/chat/completions";

  const payload = {
    model: "solar-pro3",
    messages: messagesPayload,
    reasoning_effort: "medium"
  };

  const options = {
    method: "post",
    contentType: "application/json",
    headers: {
      Authorization: "Bearer " + apiKey
    },
    payload: JSON.stringify(payload),
    muteHttpExceptions: true
  };

  const response = UrlFetchApp.fetch(url, options);
  const json = JSON.parse(response.getContentText());
  return json.choices[0].message;
}
```

## 6. 백엔드(GAS) 주요 함수 명세

1. **`doGet(e)`**:
* `Index.html` 페이지 출력 (`HtmlService.createHtmlOutputFromFile`).
* 모바일/태블릿 최적화 `meta viewport` 설정 포함.

2. **`initSpreadsheetSheets()`**:
* 스프레드시트에 `Users`, `Proposals` 탭 유무 확인 및 헤더 자동 생성.

3. **`loginOrRegisterUser(studentId, name, passwordHash)`**:
* 학생 검증 및 로그인 처리, 로그인 시각 업데이트.

4. **`loadStudentData(studentId)`**:
* 해당 학생의 1~4단계 데이터 및 진행 단계 반환.

5. **`saveStepData(studentId, name, step, formData)`**:
* 각 단계별 입력 데이터 구글 시트 반영 (`Proposals` 시트 업서트 처리).

6. **`chatWithAI(studentId, userMessage, chatHistory)`**:
* 이전 대화 내역 + 사용자 입력 메시지를 구성하여 `callUpstageSolarPro` 호출 후 결과 반환 및 구글 시트에 대화 내역 저장.
